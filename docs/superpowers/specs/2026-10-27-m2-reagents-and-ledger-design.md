## 1. 목적

과학 교사가 실험을 마치면 쓴 시약의 양을 바로 기록하고, 이 기록으로 법정 장부인 **화학약품 관리대장**(시약별, 5년 보존)을 매뉴얼 양식 그대로 출력하게 한다. 지금은 시약마다 종이 대장에 손으로 적는다. 앱은 손으로 쓰던 숫자 계산(보유량·잔량)을 대신하고, 출력물에 손 서명만 하면 되게 한다.

M2는 시약 데이터의 시작이다. M3(폐시약), M4(MSDS·경고표지), M5(보관 위치 추천)가 모두 여기서 등록한 시약을 쓴다.

## 2. 목표 / 비목표 / 실패 조건

목표
- 시약을 한 건씩 또는 엑셀 양식으로 한꺼번에 등록한다. 엑셀 양식은 앱이 만들어 준다(학교에 옮겨 올 기존 목록 형식이 없음).
- 실험 후 시약마다 사용량을 한 줄씩 빠르게 기록한다. 입고도 기록한다.
- 유독물질·사고대비물질을 CAS No.와 농도로 자동 판정한다.
- 화학약품 관리대장을 충북·서울·경기 양식으로 A4 출력한다. 설정의 "장부 양식 지역"을 따른다.
- 위치 찾기 탭에서 시약이 어느 교실 › 보관장 › 구역에 있는지 찾는다.

비목표 (M2에서 하지 않음)
- 정정 기록(재고 실사로 맞추는 별도 구분). 실제 양과 다르면 사용자가 기존 기록을 고친다. (사용자 결정. 1차 설계의 "입고/출고/폐기/정정" 4구분을 바꿈)
- 희석 용액 관리. 진한 시약으로 묽은 용액을 만들면 원래 시약에서 쓴 양만 출고로 적는다. (사용자 결정)
- 폐시약 기록과 대장(M3). 남은 시약을 버리면 출고로 적고 용도에 "폐기"라고 쓴다.
- 보관 분류·위치 추천·공존 불가(M5), MSDS·화학식 자동 채움(M4)
- 금지·허가·제한물질 자동 판정(근거 표가 자료에 없음). 사용자가 직접 표시만 한다.
- 유효기간 지남·재고 부족 알림
- 모바일 화면

실패 조건
- 출력한 대장의 항목·순서가 매뉴얼 양식과 달라 그대로 비치할 수 없다.
- 두 사람이 동시에 기록하거나 지난 기록을 고친 뒤 보유량·잔량이 틀린다.
- 실험 직후 기록이 번거로워서(여러 화면, 많은 입력) 결국 종이에 적게 된다.
- 판정 표의 오류(아래 6장) 때문에 유독물질을 "해당 없음"으로 보여 준다.

## 3. 제약

- 기존 구조를 따른다: Vite + React 화면(Vercel 하나), 학교별 GAS + 스프레드시트. GAS는 모듈 없는 전역 함수, 액션은 `Code.js`의 `registerActions()`에서 모은다. 쓰기 요청은 이미 `LockService`로 하나씩 처리된다.
- 기록 원칙(CLAUDE.md): 모든 행에 작성자·수정자·삭제자, 삭제는 표시만, 모든 변경은 이력 탭에. 시트 탭·머리글은 한국어(`Schema.js`의 `SHEET_NAMES`·`COLUMN_LABELS`).
- 날짜는 `YYYY-MM-DD` 문자열로 저장한다. `toCell`이 문자열 앞에 `'`를 붙여 시트가 날짜·숫자로 바꾸지 않는다. 수량·농도·금액은 숫자 열(`NUMBER_COLUMNS`)에 넣는다.
- GAS `API_VERSION`과 웹 `REQUIRED_API_VERSION`을 3 → 4로 함께 올린다.
- 개발용 시트 반영은 `cd gas && npm run deploy`.

## 4. 만드는 방식

검토한 방식
| 방식 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 기록만 저장, 대장 숫자는 화면에서 계산 (선택)** | 시트에는 시약 정보·현재 보유량·수불 기록(날짜, 구분, 양, 용도)만. 보유량·잔량·이월은 출력할 때 화면의 순수 함수가 날짜순으로 계산 | 지난 기록을 고쳐도 다시 계산만 하면 됨. "GAS는 얇게" 원칙과 맞음. 계산을 단위 테스트로 확인 | 시트 탭만 열어서는 대장처럼 읽히지 않음 |
| B. 서버가 대장 숫자까지 시트에 저장 | 수불 행마다 보유량·잔량 칸 | 시트만 봐도 대장처럼 보임 | 지난 기록 하나를 고치면 뒤 행 전부 다시 씀. 서버 코드·실행 시간·틀어질 위험 증가 |
| C. 시약마다 구글 시트 탭으로 대장 생성 | 시트에서 인쇄 | 시트 그대로 보관 | 1차 설계에서 "웹 A4 출력"으로 이미 정함. 시약 수백 개면 탭 수백 개 |

사용자가 **A**를 골랐다. 선생님들은 대장을 시트가 아니라 출력물로 보고, 실제 양과 다르면 기록을 고치기로 했으므로 고치기 쉬운 방식이 맞다.

## 5. 데이터

새 기록 탭 두 개(파랑)와 이력 탭 하나(회색). 공통 열(작성자·작성일시·수정자·수정일시·삭제됨·삭제자·삭제일시, ID들)은 기존 표와 같다.

### 5-1. 시약 (`Reagents`, 탭 "시약")

같은 약품명 + 같은 농도는 한 건(여러 병이어도). 염산 35%와 염산 9%는 다른 시약.

| 키 | 머리글 | 필수 | 형식·설명 |
| --- | --- | --- | --- |
| name | 약품명 | ○ | 100자 |
| concentration | 농도(%) | | 0 초과 100 이하 숫자. 비우면 순물질로 보고 판정에 100%를 쓴다 |
| formula | 화학식 | | 50자 |
| casNo | CAS No. | | `숫자-숫자2-숫자1` 형식 검사, 체크 숫자도 검사 |
| grade | 규격 | | `시약용` · `공업용` · 빈칸 (서울 양식) |
| unit | 단위 | ○ | `mL` · `g` |
| mainUse | 주용도 | | 기본값 "실험용" (경기·서울 양식) |
| expiryDate | 유효기간 | | 날짜 |

- `stock`은 `records.update`로 쓸 수 없다.

### 5-2. 시약 수불 (`ReagentTx`, 탭 "시약 수불")

| 키 | 머리글 | 형식·설명 |
| --- | --- | --- |
| reagentId | 시약 ID | 오른쪽 ID 열 |
| reagentName | 약품명 | 사람이 읽는 칸(기록할 때의 이름. 시약 이름을 바꾸면 함께 바꾸지는 않음) |
| date | 일자 | 날짜. 미래 날짜 거부 |
| kind | 구분 | `initial`(기초 재고) · `in`(입고) · `out`(출고). 탭에는 한국어로 보이게 |
| amount | 수량 | 0보다 큰 숫자, 소수 셋째 자리까지 |
| purpose | 용도 | 출고: 실험 이름 등(필수). 입고: 구입처(선택, 시약의 구입처가 기본값) |
| price | 금액(원) | 입고만, 선택 (서울 양식 "취득 금액") |
| note | 비고 | 200자 |

- 기록자는 공통 열의 작성자다. 대장의 확인·결재 칸은 비워 두고 손으로 서명한다(사용자 결정).
- `initial`은 시약 등록 때 서버가 함께 만든다(한 시약에 하나). 등록할 때 보유량 0이면 수량 0인 기초 재고를 만든다(이 경우만 0 허용).
- **기초 재고 날짜(기준일)는 사용자가 정한다**(사용자 결정). 학년도 첫날(3월 1일)로 두고 그 뒤 종이 대장의 기록을 날짜를 지정해 옮겨 적을 수도 있고, 학년도 중간 날짜로 두고 그날부터 시작할 수도 있다. 입고·출고 기록도 모두 날짜를 사용자가 지정한다(기본은 오늘). 나중에 입력한 지난 날짜의 기록도 대장에는 날짜순으로 들어간다.

### 5-3. 이력

- 새 이력 탭 "시약 이력": `HISTORY_GROUP_OF_TABLE`에 `Reagents`, `ReagentTx` → `reagents`.
- 시약 상세 화면의 "이력 보기"는 시약과 그 시약의 수불 기록 변경을 함께 보여 준다.

## 6. 유독물질·사고대비물질 판정

- 근거: 경기 부록9 「학교에서 사용하는 화학물질의 유해화학물질 기준농도」 46종. `web/src/data/hazardThresholds.ts`에 물질명·화학식·CAS No.·유독물질 기준농도·사고대비물질 기준농도(없으면 "해당없음")를 넣고 출처를 주석으로 단다.
- **원문 오류 두 곳은 고쳐서 넣고 주석에 남긴다.**
  - 14번 시안화 칼륨 CAS `97-1-90` → `151-50-8` (원문 번호는 CAS 체크 숫자 검사도 통과하지 못함)
  - 18번 에탄올 화학식 `C2H2O` → `C2H5OH`
- 판정 함수(`web/src/domain/hazard.ts`, 순수 함수): CAS No.가 표에 있으면 농도(비면 100) ≥ 기준농도 → `해당`, 미만 또는 기준 "해당없음" → `해당 없음`. CAS가 없거나 표에 없으면 → `판정 불가`.
- 화면: `판정 불가`면 "직접 확인 필요 – 화학물질정보처리시스템(kreach.me.go.kr)에서 확인" 안내를 보여 주고, 사용자가 해당/해당 없음을 직접 고를 수 있다(`hazardManual` = 참). 자동 판정 값을 사용자가 바꿔도 같다.
- 판정은 화면에서 저장 직전에 계산해 함께 보낸다. CAS·농도를 고치면 다시 계산한다(`hazardManual`이 참이면 그대로 둠).
- 대장의 유해화학물질 표시: 유독물질 또는 사고대비물질이 `해당`이면 유해화학물질로 보고 약품명을 형광 표시한다.
- 농도를 M(몰농도)로 아는 경우: 농도 칸은 %만 받는다. 안내 문구로 "%로 모르면 비워 두고 판정을 직접 지정"을 보여 준다.
- **M4와의 연결**(사용자 의견): M4에서 data.go.kr MSDS API를 붙이면, 표에 없어 `판정 불가`인 시약을 API의 유해성 정보와 비교해 판정을 제안할 수 있다. M2는 판정 값 `판정 불가`와 `hazardManual`을 구분해 저장해 두어, M4가 "아직 사람이 정하지 않은 판정 불가 시약"만 골라 다시 판정할 수 있게 한다.

## 7. 서버(GAS)

`gas/src/Reagents.js`에 시약 전용 액션을 둔다. 공통 저장 함수(`dbCreate`, `dbUpdate`, `dbSoftDelete`, `dbRestore`, 이력 기록)를 그대로 쓴다. 모두 `auth: 'user'`.

| 액션 | 하는 일 |
| --- | --- |
| `reagents.list` | 시약 목록(삭제 포함 여부 선택) |
| `reagents.create` | 시약 1건 + 기초 재고 수불 1건. 입력 검사, 중복 검사, `stock` = 기초 재고 |
| `reagents.createMany` | 엑셀 일괄 등록. 줄마다 같은 검사, 한 줄이라도 틀리면 전부 저장하지 않고 줄 번호와 이유를 돌려줌. 파일 안 중복도 검사 |
| `reagents.update` | 시약 정보 수정(`stock` 제외) |
| `reagents.delete` / `reagents.restore` | 시약 삭제 표시·복구. 수불 기록은 그대로 둔다. 복구할 때 같은 이름·농도의 살아 있는 시약이 있으면 거부 |
| `reagentTx.list` | 한 시약의 수불 기록, 또는 기간 안의 모든 수불 기록(대장 전체 출력용) |
| `reagentTx.create` | 입고·출고 1건. 기록 후 그 시약의 잔량 흐름이 음수가 되면 거부("남은 양 ○○ mL보다 많습니다") |
| `reagentTx.update` / `reagentTx.delete` / `reagentTx.restore` | 고치기·삭제·복구. 기초 재고는 수량·날짜만 고칠 수 있고 삭제할 수 없다 |

- 수불을 바꿀 때마다 그 시약의 살아 있는 수불 기록 전체를 날짜순(같은 날은 작성일시순)으로 다시 더해서 **어느 시점에서도 음수가 아닌지** 확인하고, `stock`을 다시 계산해 저장한다. 같은 계산 규칙을 화면 쪽 순수 함수와 맞춘다(같은 시험 사례를 양쪽에 둔다).
- 날짜는 기초 재고보다 앞설 수 없다.
- 수량 합계는 소수 셋째 자리에서 반올림한다(부동소수점 오차 방지).
- `Reagents`, `ReagentTx`는 `RECORD_TABLES`에 넣지 않는다(일반 `records.*`로 `stock`을 우회해 쓰지 못하게).
- 보관장 구역 삭제(M1의 보관장 크기 줄이기 포함)와 보관장·교실 삭제: 그 안에 살아 있는 시약이 있으면 서버가 거부하고 시약 이름을 알려 준다("먼저 시약의 보관 위치를 옮겨 주세요"). M1 코드(`Records.js`의 삭제 처리)를 함께 고친다.

## 8. 화면

메뉴(아이콘 사이드바)에 **시약**, **위치 찾기**를 추가한다(교실·보관장 아래).

### 8-1. 시약 목록 (`/reagents`)
- 검색(약품명·CAS No.·화학식 일부), 유해화학물질만 보기.
- 열: 약품명(유해화학물질은 표시), 농도, 현재 보유량 + 단위, 보관 위치(교실 › 보관장 › 구역), 유효기간.
- 줄마다 **사용 기록**, **입고** 버튼. 이름을 누르면 상세.
- 위쪽 버튼: 시약 등록, 엑셀로 등록, 대장 출력, 삭제된 시약 보기.

### 8-2. 사용 기록 창 (가장 자주 쓰는 화면)
- 시약 이름·현재 보유량이 위에 보인다.
- 칸: 일자(오늘), 사용량(단위 표시), 용도(필수, 최근에 쓴 용도 몇 개를 고를 수 있게), 비고.
- "기록 후 남는 양"을 입력하는 동안 보여 준다. 남은 양보다 많으면 저장 버튼을 막고 이유를 보여 준다.
- 저장하면 창이 닫히고 목록의 보유량이 바뀐다. 목표: 목록에서 클릭 → 숫자·용도 입력 → 저장, 세 번 안에 끝.

### 8-3. 입고 창
- 칸: 일자(오늘), 수량, 구입처(시약의 구입처가 기본), 금액(선택), 비고.

### 8-4. 시약 등록 / 상세 (`/reagents/new`, `/reagents/:id`)
- 5-1의 항목. 보관 구역은 교실 → 보관장 → 구역 순서로 고른다.
- 등록 화면에는 기초 재고량과 기준일 칸이 있다. 기준일은 기본 오늘이고, "이 학년도 3월 1일" 버튼으로 바로 바꿀 수 있다.
- 사용 기록·입고 창의 일자는 기본 오늘이고 지난 날짜로 바꿀 수 있다(종이 대장을 옮겨 적을 때). 기준일보다 앞선 날짜는 받지 않는다.
- 판정 결과를 바로 보여 주고(6장), 바꿀 수 있다.
- 상세 화면: 정보 수정, 학년도별 수불 기록 표(고치기·삭제), 이 시약 대장 출력, 이력 보기, 삭제.

### 8-5. 엑셀로 등록 (`/reagents/import`)
- **양식 내려받기**: 앱이 xlsx를 만든다.
  - "입력" 시트: 5-1의 사용자 입력 항목 + "기초 재고량"(필수) + "기준일"(선택). 첫 줄 머리글(필수는 표시), 둘째 줄 예시(올릴 때 "예시" 표시가 있으면 건너뜀).
  - 기준일을 비운 줄은 올리기 화면의 "기준일" 칸 값을 쓴다(기본은 그 학년도 3월 1일). 3월 1일 기준 잔량으로 등록한 뒤 종이 대장의 기록을 옮겨 적거나, 오늘 기준 잔량으로 지금부터 시작할 수 있다.
  - 고르는 칸은 목록 선택: 단위(mL·g), 규격, 예/아니오 칸, **보관 위치**(이 학교의 "교실 › 보관장 › 구역" 목록. 구역 이름이 없으면 "3단 2칸").
  - "안내" 시트: 열 설명, 날짜 형식(2026-03-16), 농도는 %만, 같은 약품·같은 농도는 한 줄.
- **올리기**: 브라우저에서 읽어 줄마다 검사 → 미리보기 표(오류 줄은 빨간색 + 이유, 판정 결과 표시) → 오류가 없을 때만 "저장".
- 이미 등록된 시약(같은 약품명 + 농도)과 겹치는 줄은 오류가 아니라 **"이미 등록됨 – 건너뜀"**으로 미리보기에 회색으로 보이고 저장하지 않는다. 파일 안에서 서로 겹치는 줄은 오류다.
- 많으면 200줄씩 나눠 보낸다. 나눠 보낸 중간에 실패하면 이미 저장된 줄 수를 알려 주고, 같은 파일을 다시 올리면 저장된 줄은 "이미 등록됨"으로 건너뛴다. 서버(`reagents.createMany`)도 같은 규칙: 이미 있는 시약은 건너뛰고 건너뛴 줄 번호를 돌려준다.

### 8-6. 대장 출력 (`/reagents/ledger`)
- 학년도 선택(기본: 지금 학년도. 3월 1일 ~ 이듬해 2월 말일), 시약 선택(전체 / 고른 시약).
- "전체"는 그 학년도에 살아 있는 수불 기록이 있거나 학년도 시작 때 잔량이 0보다 큰 시약. 대장은 5년 보존하는 법정 장부이므로, 그 해에 기록이 있으면 **나중에 삭제한 시약도 포함**한다(그 해 이후 삭제). 약품명 가나다순.
- "고른 시약"의 선택 목록에도 삭제한 시약을 "(삭제됨)" 표시와 함께 보여 준다.
- 시약 하나가 A4 한 장부터 시작하고, 줄이 넘치면 다음 장에 머리를 다시 찍고 이어 간다. 마지막 장은 빈 줄로 채워 손으로 더 적을 수 있게 한다.
- 브라우저 인쇄(`@page` A4, 충북·경기 세로, 서울 가로). 인쇄 전 미리보기는 같은 화면.
- 지역별 구성 (시안 확인: `.superpowers/brainstorm/` ledger-print.html)

| | 충북 서식3 | 경기 서식3 | 서울 |
| --- | --- | --- | --- |
| 제목 | 화학물질 관리대장 | ○○학년도 과학실험실 화학약품 관리(출납)대장 | ○○학년도 과학실험실 화학약품 관리(출납)대장 |
| 머리 | 약품명, CAS No., 금지·허가·제한·유독·사고대비물질 ( ○ ) | 약품명, 유효기간, 농도, 주용도, 유해화학물질 여부, 단위 | 품명(+화학식), 규격, 단위, 독극물, 주용도, 유효기간 |
| 칸 | 연월일, 수불구분, 수불량, 보유량, 잔량, 용도, 확인, 비고 | 수불일자, 수불구분, 수불량, 보유량, 잔량, 용도, 확인(서명) | 일자, 결재(부장·담당), 적요, 취득(수량·금액), 사용량, 재고량, 비고 |
| 아래 문구 | 5년 비치 근거, 형광 표시 권장 | 에듀파인 미등록 시 사용 | 같음 |

- 줄 만드는 규칙(`web/src/domain/ledger.ts`, 순수 함수):
  - 첫 줄: 학년도 시작 전에 기록이 있으면 **이월**(날짜 = 학년도 첫날, 잔량만). 기초 재고가 이 학년도 안이면 **기초 재고** 줄(날짜 = 기준일, 잔량만).
  - 입고: 수불구분 "입고", 수불량, 보유량(직전 잔량), 잔량, 용도 = 구입처. 서울: 적요 "구입 (구입처)", 취득 수량·금액, 재고량.
  - 출고: 수불구분 "출고", 용도 = 실험 이름. 서울: 적요 = 용도, 사용량, 재고량.
  - 비고 = 수불 기록의 비고. 확인·결재 칸은 항상 빈칸.
  - 날짜순, 같은 날은 작성일시순. 삭제된 기록은 빠진다.
- 경기 "유해화학물질 여부"는 ○/×, 충북 머리 ○ 칸은 해당하는 것만 ○.
- **판정 불가인 시약**(사용자 결정): 빈칸이나 ×로 찍으면 "해당 없음"으로 읽히므로, 해당 칸에 "확인 필요"라고 찍는다(충북 유독물질·사고대비물질 칸, 경기 유해화학물질 여부 칸). 서울 양식에는 유해화학물질 칸이 없으므로 표시하지 않는다. 인쇄 전에 "판정이 안 된 시약 ○개" 안내와 각 시약 화면으로 가는 링크를 보여 준다(인쇄는 막지 않음).

### 8-7. 위치 찾기 (`/find`)
- 검색칸 하나(약품명·CAS No.·화학식 일부). 결과마다 약품명·농도, "교실 › 보관장 › 구역", 보유량. 위치를 아직 안 정한 시약은 "위치 미지정".
- 결과를 누르면 보관장 화면(`/cabinets/:id?zone=<구역 ID>`)으로 가서 그 구역을 강조한다.
- 1차 설계대로 2차에서 교구도 같은 탭에서 찾는다(지금은 시약만, 종류 필터 없음).

사용자가 정한 것 (2026-10-27)

Claude가 정한 것 (확인 부탁)
1. 서울 양식도 학년도로 끊고, 제목의 "2025년"을 "○○학년도"로 바꿔 출력한다.
2. 수불 구분은 기초 재고·입고·출고 셋. 남은 시약 폐기는 출고 + 용도 "폐기".
3. 같은 약품명 + 같은 농도는 중복 등록을 막는다.
4. 농도 칸은 %만 받고, 비우면 판정에 100%를 쓴다.
5. 부록9 원문의 시안화 칼륨 CAS, 에탄올 화학식 오류를 고쳐서 쓴다.
6. 엑셀 일괄 등록은 한 줄이라도 틀리면 전부 저장하지 않는다(미리보기에서 먼저 고치게). 단, 이미 등록된 시약과 겹치는 줄은 오류가 아니라 건너뛴다.
9. 대장 "전체" 출력에는 그 학년도에 기록이 있으면 나중에 삭제한 시약도 넣는다(법정 장부 5년 보존).
10. 시약이 들어 있는 구역·보관장·교실은 삭제할 수 없다(먼저 시약 위치를 옮김).
7. 출고 기록의 용도는 필수, 입고 기록의 금액은 선택.
8. 엑셀 파일 처리 라이브러리는 ExcelJS(목록 선택 칸을 만들 수 있음)를 엑셀 화면에서만 불러 쓴다. 1차 설계의 SheetJS는 npm 배포판이 오래되어 바꾼다.
