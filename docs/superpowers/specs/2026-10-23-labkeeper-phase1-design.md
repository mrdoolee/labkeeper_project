# LabKeeper 1차 개발 설계

작성일: 2026-10-23
관련 문서: [manual-review.md](../../manual-review.md), [phase1-scope.md](../../phase1-scope.md), CLAUDE.md

## 1. 목적과 배경

학교 과학실의 **시약과 과학 교구를 관리하는 웹앱**이다. 1차는 시약을 중심으로 만든다.

학교 과학실 담당 교사는 시약 출납, 폐수 처리, 월간 안전점검을 법정 장부에 기록하고 보관해야 한다. 지금은 대부분 수기로 쓰고, 보관 위치·MSDS·경고표지 관리는 따로 한다. LabKeeper는 기록을 한 번 입력하면 **매뉴얼 양식 그대로 장부가 출력**되게 하고, 시약을 **어디에 두어야 하는지**와 **어떤 위험이 있는지**를 함께 보여 준다.

사용자
- 운영 교사(관리자) 1명: 계정 관리, 학교·과학실·보관장 설정, 전체 관리
- 일반 교사(다른 과학 교사) 여러 명: 시약 등록·기록, 점검표 입력, 출력

## 2. 목표 / 비목표 / 실패 조건

목표
- 충북 서식 1·3·4·5를 운영하고, 서울·경기 양식으로 바꿔 출력할 수 있다.
- 시약을 한 건씩 또는 엑셀 양식으로 한꺼번에 등록한다.
- 시약 입고·사용·폐기, 폐수 발생·처리, 월간 점검을 기록하면 장부가 자동으로 채워진다.
- 시약 등록 시 유독물질·사고대비물질 여부를 자동 판정한다.
- 시약을 넣을 보관 구역을 추천하고, 함께 두면 위험한 시약을 경고하고, 재배치 제안(정돈)을 보여 준다.
- MSDS를 안전보건공단 API로 불러와 화면에서 보고, GHS 경고표지를 출력한다.
- 업체 MSDS는 보유 여부를 표시하고, 파일이 있으면 첨부한다.

비목표 (1차에서 하지 않음)
- 과학 교구 등록 (2차)
- 모바일 전용 화면 (PC 완성 후)
- 서식2(유해화학물질 표시), 서식6(사안 보고), 유해화학물질 취급시설 주간 점검대장, 시약장 목록표
- 에듀파인 연동
- 구글 로그인(OAuth)

실패 조건 (동작해도 실패로 보는 것)
- 출력한 장부가 매뉴얼 양식과 항목·순서가 달라 그대로 쓸 수 없다.
- API로 받은 MSDS를 법적으로 유효한 MSDS처럼 보이게 한다. 화면에 항상 "참고자료(안전보건공단)"로 표시해야 한다.
- 기록이 사라지거나, 두 사람이 동시에 기록할 때 잔량이 틀어진다.
- 비밀번호가 스프레드시트에 평문으로 남는다.

## 3. 제약

- **화면**: Vite + React + TypeScript, Vercel에 배포. PC 브라우저 기준.
- **서버**: Google Apps Script(GAS) 웹앱. 사용자의 구글 계정으로 배포하므로 Claude가 직접 배포할 수 없다. 코드는 저장소에 두고 사용자가 붙여 넣거나 clasp로 올린다.
- **DB**: Google 스프레드시트 1개. 시트 하나가 표 하나.
- 화면과 GAS의 주소가 다르다. 브라우저 사전 확인 요청(CORS preflight)을 피하려고 요청은 `POST` + `Content-Type: text/plain`으로 보내고 본문에 JSON을 담는다. GAS는 `ContentService`로 JSON을 돌려준다.
- GAS 실행 시간은 요청당 6분 제한, 외부 API 호출은 하루 2만 회 한도. 무거운 계산은 화면(브라우저)에서 한다.
- data.go.kr API 키는 GAS의 스크립트 속성에만 저장한다. 화면 코드에 넣지 않는다.
- 이 개발 환경(클라우드 세션)은 data.go.kr·msds.kosha.or.kr 접속이 막혀 있다. API 응답 형식은 사용자가 키를 받은 뒤 GAS에서 확인한다.

| --- | --- | --- | --- |
| 화면 배포 | Vercel에 따로 호스팅 (사용자 결정) | GAS가 화면까지 제공 | 사용자 결정 |

| 엑셀 일괄 등록 | 브라우저에서 처리(SheetJS) (Claude 결정) | GAS에서 처리 | 빠르고 GAS 시간 제한과 무관 |

## 5. 구조

```
labkeeper_project/
  web/                 Vite + React + TypeScript (화면)
    src/domain/        순수 로직: 유해물질 판정, 보관 추천, 공존 불가 검사, 경고표지 규칙, 장부 계산
    src/data/          고정 자료: 기준농도표, 보관 분류, 공존 불가표, 지역별 서식 정의
    src/api/           GAS 호출
    src/pages/         화면
    src/print/         인쇄용 양식 화면
  gas/                 Apps Script 코드 (.gs)
  docs/
```

원칙: **GAS는 얇게.** 로그인, 표 읽기·쓰기, 잠금, 외부 API 대리 호출, 드라이브 파일 저장만 한다. 판정·추천·장부 계산은 `web/src/domain`의 순수 함수로 두고 단위 테스트한다.

### 5-1. 요청 형식

```
POST <GAS 웹앱 주소>
Content-Type: text/plain
{ "action": "reagents.list", "token": "...", "payload": { ... } }
→ { "ok": true, "data": ... } 또는 { "ok": false, "error": "메시지" }
```

### 5-2. 로그인

- 비밀번호 저장: 사용자별 무작위 salt + SHA-256을 여러 번 반복한 값(GAS `Utilities.computeDigest`). 평문 저장 금지.
- 로그인 성공 시 무작위 토큰 발급, `CacheService`에 6시간 보관(요청할 때마다 연장). 토큰이 없거나 만료되면 다시 로그인.
- 첫 실행: 사용자 시트가 비어 있으면 운영 교사 계정 만들기 화면을 보여 준다.
- 운영 교사가 일반 교사 계정을 만들 때 임시 비밀번호를 발급하고, 첫 로그인 때 비밀번호를 바꾸게 한다. 비밀번호를 잊으면 운영 교사가 임시 비밀번호로 초기화한다.
- 같은 아이디로 연속 5회 실패하면 10분간 로그인 막기.

### 5-3. 권한 (사용자 결정)

- 운영 교사와 일반 교사는 **같은 기능을 모두 쓸 수 있다.** 설정 변경과 기록 삭제도 일반 교사가 할 수 있다.
- 운영 교사만 하는 일은 **계정 관리**(계정 만들기, 비밀번호 초기화, 사용 중지)뿐이다.

### 5-4. 기록 원칙: 누가 했는지 항상 남긴다 (사용자 결정, 앱 전체에 적용)

- 모든 표의 모든 행에 작성자·작성일시, 마지막 수정자·수정일시를 남긴다.
- 삭제는 실제로 지우지 않고 "삭제됨" 표시와 삭제자·삭제일시를 남긴다(복구 가능). 장부 출력과 잔량 계산에서는 빠진다.
- 추가·수정·삭제는 모두 변경 이력(AuditLog)에 누가, 언제, 무엇을, 바꾸기 전·후 값으로 남긴다. 설정 변경도 포함한다.
- 화면의 각 기록에서 "이력 보기"로 변경 이력을 볼 수 있다.
- 이 원칙은 앞으로 추가할 기능(2차 교구 등)에도 그대로 적용한다.

## 7. 기능별 설계

### 7-1. 장부 출력 (서식 1·3·4·5, 지역별)

- `web/src/data/forms/`에 지역별 서식 정의(제목, 항목 문구, 열 구성, 서명란, 보존 안내)를 둔다. 인쇄 화면은 이 정의를 읽어 A4로 그린다.
- 지역별 대응

| 종류 | 충북 (기본) | 서울 | 경기 |
| --- | --- | --- | --- |
| 월간 안전점검표 | 서식1 A형(1회분)·B형(12개월) | 서식2 점검 체크리스트(1회분) | 서식1 자체 점검표(12개월) |
| 화학약품 관리대장 | 서식3 화학물질 관리대장 | 서식8 화학약품 관리(출납)대장 | 서식3 화학약품 관리(출납)대장 |
| 폐수·폐시약 대장 | 서식4 폐수·폐기물 관리(처리)대장 | 서식6 폐수 관리대장·폐시약 관리대장 | 서식4 폐수·폐시약 관리대장 |
| 폐수 점검표 | 서식5 A형·B형 | 서식7 점검결과표(12개월) | 서식5 자체 점검표(12개월) |

- 점검 항목 수와 문구는 지역마다 다르다. 점검 기록은 지역별 항목 ID로 저장하고, 지역을 바꾸면 그 지역 양식의 점검표를 새로 입력한다(항목 자동 변환은 하지 않음).
- 장부는 학년도(3월 1일 ~ 이듬해 2월 말일) 단위로 출력한다. 폐수 대장의 이월량은 이전 학년도 마지막 잔량이다. 12개월 점검표의 월 순서는 각 지역 양식을 따른다(충북 1~12월, 경기 3~2월 등).
- 서명란은 비워 두고 출력한다. 점검자·확인자 이름은 설정값으로 채운다.
- 유해화학물질은 화학약품 관리대장에서 약품명을 강조 표시한다(충북 권장).

### 7-2. 시약 등록

- 한 건씩: 약품명 또는 CAS No.를 입력하면 MSDS API로 물질을 찾아 화학식·CAS No.를 채워 준다(찾지 못하면 직접 입력).
- 엑셀 일괄 등록: 양식(xlsx) 내려받기 → 입력 → 올리기 → 미리보기에서 줄별 오류 표시 → 확인 후 저장. 양식에는 "입력" 시트(필수 열, 예시 1줄)와 "안내" 시트(열 설명, 단위·날짜 형식)를 둔다. 같은 방식을 2차 교구 등록에 재사용한다.
- 등록 시 입고 수불 기록 1건을 자동으로 남긴다(기초 재고).

### 7-3. 유독물질·사고대비물질 판정

- 경기 매뉴얼 부록 9의 46종 기준농도표를 `web/src/data`에 넣는다.
- CAS No.로 표를 찾아 농도 ≥ 기준농도이면 해당으로 판정한다.
- 표에 없는 물질은 "판정 불가 – 직접 확인"으로 표시하고 화학물질정보처리시스템(kreach) 안내를 보여 준다. 사용자가 직접 지정할 수 있다.

### 7-4. 보관 위치 추천과 정돈

같은 약품은 여러 병이어도 **보관 위치를 한 곳**으로 둔다(사용자 결정: 학교 시약장은 많아야 2개).

**보관장 종류** (충북 보관장별 분류 예시)
- 밀폐형 약품장: 위험성이 크거나 냄새·유해 증기가 나는 약품 (서울·경기도 같은 원칙)
- 가연성 물질 전용 보관장: 인화성·휘발성 물질. 없으면 밀폐형 약품장의 무기화합물과 분리된 칸에 둔다(충북·서울)
- 일반 약품 보관장: 냄새·증기가 없고 위험성이 낮은 약품

**보관 분류 8가지** (매뉴얼 3종 대조 결과)

| 분류 | 예시 | 기본 보관장 | 근거 |
| --- | --- | --- | --- |
| 무기산 | 염산, 황산, 질산, 인산 | 밀폐형 | 충북 "산", 서울 "무기산 분리 보관", 경기 "무기 산" |
| 유기산 | 아세트산(빙초산), 로르산 | 밀폐형 | 경기 "유기 산"을 따로 둠, 서울 "무기·유기 분리", 질산↔아세트산 공존 불가 |
| 염기 | 수산화 나트륨·칼륨·칼슘·바륨, 암모니아수 | 밀폐형 | 충북 "염기", 경기 "무기·유기 염기" |
| 산화제 | 과망가니즈산칼륨, 질산칼륨, 질산은, 과산화수소, 염소산칼륨, 다이크로뮴산칼륨, 아질산나트륨, 아이오딘, 브로민 | 밀폐형 | 충북 "위험이 높은 무기 화합물", 경기 "산화제", 서울 "폭발 위험이 있는 약품" |

처음 안(8가지)과 달라진 점
- "산"을 **무기산과 유기산으로 나눴다.** 경기 매뉴얼이 유기·무기 산을 따로 분류하고, 서울 매뉴얼이 무기산 분리 보관과 질산↔아세트산 공존 불가를 명시하기 때문이다.
- "독성"을 분류에서 빼고 **추가 표시**로 바꿨다. 서울 매뉴얼의 극약·독약 목록에 염산·황산·질산·수산화나트륨처럼 다른 분류에 속하는 약품이 함께 들어 있어서, 분류 하나로는 표현할 수 없다.

**분류와 별개로 붙는 표시** (보관 조건을 더 엄격하게 만듦)
- 독극물(극약·독약·맹독성): 일반 시약과 별도 칸, 잠금 보관장(이중 잠금 권장), 라벨에 빨간 "위험" 표시 (서울, 경기, 충북·경기 점검표 "독극물 특별관리")
- 유해화학물질(7-3 판정 결과): 별도 보관, 잠금, 취급주의 표시 (경기)
- 유해 증기·냄새 발생: 밀폐형 약품장만 허용 (서울, 경기)
- 직사광선 차단 필요(질산, 과산화수소 등): 갈색병·어두운 곳 안내 (충북 공존 표, 서울)

**분류 정하는 순서**: ① 충북 분류표 등 매뉴얼에 나온 학교 시약(약 70종)을 CAS No.로 찾기 → ② MSDS API의 유해성 분류로 추정(인화성 액체 → 인화성·휘발성, 산화성 → 산화제, 물반응성 → 금속·물반응성, 급성 독성 구분 1~2 → 독극물 표시 제안) → ③ 정하지 못하면 사용자가 선택.

**구역 설정**: 구역마다 보관장 종류에 따른 기본 허용 분류가 들어가고, 바꿀 수 있다. 구역에 잠금 여부를 둔다.

**추천 순서**: 분류가 허용된 구역 → 독극물·유해화학물질이면 잠금 구역만 → 공존 불가 물질이 없는 곳 → 아래쪽 칸 우선(경기 "눈높이 아래 보관") → 시약이 적은 곳(경기 "밀집 보관 지양").

**공존 불가 경고**: 서울 참고자료 2와 충북 부록의 표를 규칙으로 정리해, 같은 구역에 함께 있으면 경고한다.

**정돈**: 규칙에 어긋난 시약(분류가 허용되지 않은 구역, 공존 불가, 잠금 필요한데 잠금 없음)과 옮길 구역 제안을 한 화면에 보여 준다. 같은 구역 안에서는 가나다순 정렬을 권한다(서울 "1차 분류 후 가나다순"). 옮기기는 사용자가 확인한 것만 반영한다.

**원문 확인 필요**: 충북 계획 53쪽 표는 밀폐형 약품장 안에서 산과 염기를 상단·하단으로 나누어 그린 것으로 보이지만, 텍스트 변환이 깨져 어느 쪽이 위인지 확인하지 못했다. 원문 PDF로 확인해 추천 규칙에 반영한다.

### 7-5. MSDS와 GHS 경고표지

- GAS가 API를 대신 호출한다(키 보호). 받은 내용은 MsdsCache에 저장해 같은 물질은 다시 부르지 않는다. "새로 불러오기" 버튼으로 갱신한다.
- 화면: 16개 항목을 펼쳐 보기. 상단에 "참고자료 – 안전보건공단 제공, 법적 비치용 아님"을 항상 표시. 업체 MSDS 보유 여부와 첨부 파일 링크를 함께 보여 준다.
- 업체 MSDS 파일: 화면에서 올리면 GAS가 학교 구글 드라이브의 LabKeeper 폴더에 저장하고 파일 ID를 기록한다.
- 경고표지(GHS): API의 2번 항목(유해성·위험성)에서 그림문자, 신호어, 유해·위험 문구, 예방조치 문구를 읽는다. 고시 규칙을 적용한다.
  - "해골"과 "감탄부호"가 함께면 해골만, "부식성"과 "자극성"이 함께면 부식성만, "호흡기 과민성"과 피부 과민성·자극성이 함께면 호흡기 과민성만, 그림문자는 최대 4개
  - "위험"과 "경고"가 함께면 "위험"
  - 예방조치 문구 7개 이상이면 예방·대응·저장·폐기 각 1개 이상 포함해 6개, 나머지는 "MSDS 참고"
  - 100g·100mL 이하 용기는 명칭, 그림문자, 신호어, 공급자 정보만
  - 바탕 흰색, 글씨·테두리 검정, 그림문자 테두리 빨강
- 라벨 크기: 용기 용량에 따라 고시 최소 면적을 지키는 크기를 고르고, A4 한 장에 여러 장을 배치해 인쇄한다.
- GHS 그림문자 이미지(9종)는 저장소에 SVG로 넣는다.

## 12. 결정 기록

사용자가 정한 것
- 모든 사용자가 모든 기능을 쓴다. 계정 관리만 운영 교사가 한다.
- 모든 기록에 작성자를 남기고, 이 원칙을 앱 전체에 적용한다.
- 같은 약품은 여러 병이어도 한 건, 보관 위치는 한 곳.

Claude가 정한 것 (확인 부탁)
1. 계정 관리(계정 만들기, 비밀번호 초기화, 사용 중지)는 운영 교사만 한다.
2. 로그인 유지 6시간, 5회 실패 시 10분 잠금.
3. 지역 양식을 바꾸면 점검표 항목은 자동 변환하지 않고 그 지역 양식으로 새로 입력한다.
4. 삭제는 "삭제됨" 표시로 처리하고 복구할 수 있다.
5. 업체 MSDS 파일은 학교 구글 드라이브의 LabKeeper 폴더에 저장한다.
6. 장부는 학년도(3월~이듬해 2월) 단위로 출력한다.
7. 입고 기록에 금액(선택)을 둔다. 서울 화학약품 관리대장에 금액 칸이 있어서다.
