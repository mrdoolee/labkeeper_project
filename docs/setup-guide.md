# LabKeeper 설치 안내 (학교 운영 교사용)

학교에서 LabKeeper를 처음 시작하는 **운영 교사**를 위한 안내입니다. 순서대로 따라 하면 됩니다.

LabKeeper는 두 부분으로 나뉩니다.

- **공용 화면**: 모든 학교가 함께 쓰는 웹 주소(https://labkeeper-trdooleel.vercel.app/). 이미 준비되어 있어 학교가 따로 만들 필요가 없습니다. 데이터를 저장하지 않습니다.
- **학교 스프레드시트**: 학교마다 하나. 구글 스프레드시트에 붙은 Apps Script(GAS)가 그 학교의 데이터를 저장하고 화면과 주고받습니다. 데이터는 이 시트에만 있습니다.

처음 한 번만 하면 되고, 20분 정도 걸립니다.

> 학교 Google Workspace(교육청 계정)는 웹 앱을 "모든 사용자"에게 열 수 없게 막혀 있는 경우가 있습니다. 그러면 공용 화면에서 연결되지 않으니, **개인 Gmail 계정**으로 아래 과정을 진행하세요.

## 1. 원본 시트 복사하기

1. 이 링크를 엽니다: **<원본 사본 링크>**
2. **사본 만들기**를 누릅니다. 내 드라이브에 코드가 들어 있는 빈 시트가 생깁니다. 이름은 자유롭게 바꿔도 됩니다(예: `LabKeeper - ○○중학교`).
   - 이 시트에 모든 기록이 저장됩니다. 다른 사람과 공유하지 마세요. 선생님들은 시트가 아니라 웹 화면으로 씁니다.
3. 시트를 처음 열면 상단에 **LabKeeper** 메뉴가 생깁니다(몇 초 걸릴 수 있습니다).

## 2. 웹 앱으로 배포하기

1. 시트 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
2. (권장) 왼쪽 톱니바퀴 **프로젝트 설정**에서 **시간대**를 `(GMT+09:00) 서울`로 바꿉니다.
3. 오른쪽 위 **배포 → 새 배포**를 누르고, **유형 선택**(톱니바퀴)에서 **웹 앱**을 고릅니다.
4. 다음처럼 설정하고 **배포**를 누릅니다.
   - **다음 사용자 인증 정보로 실행: 나**
   - **액세스 권한이 있는 사용자: 모든 사용자**
     - LabKeeper가 교사별 아이디·비밀번호로 사용자를 확인하므로, 구글 로그인 없이 접속할 수 있게 열어 둡니다. 시트 자체는 여전히 선생님만 볼 수 있습니다.
5. 권한 승인 창이 뜨면 **액세스 승인 → 본인 계정 선택**을 누릅니다.
   - "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음) → 허용**을 누릅니다. 선생님 시트에 든 스크립트라서 나오는 안내입니다.
6. **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사해 둡니다.

## 3. 운영 교사 계정 만들기 (시트에서)

1. 시트로 돌아와 **LabKeeper → 운영 교사 계정 만들기**를 누릅니다. (처음이면 권한 승인을 한 번 더 묻습니다.)
2. 아이디(영문 소문자·숫자·`. _ -`, 3~30자), 이름, 비밀번호(8자 이상)를 정합니다.

첫 계정은 이렇게 시트에서만 만들 수 있습니다. 웹 주소를 아는 사람이 먼저 운영 교사 계정을 가로챌 수 없게 하기 위해서입니다.

## 4. 공용 화면에서 연결하고 로그인하기

1. 공용 화면 주소를 엽니다: **https://labkeeper-trdooleel.vercel.app/**
2. **스프레드시트 연결** 화면에 2단계에서 복사한 웹 앱 URL을 붙여 넣고 **연결 테스트**를 누릅니다.
   - 실패하면: 주소가 `…/exec`로 끝나는지, 액세스 권한이 "모든 사용자"인지 확인하세요. 방금 배포했다면 10초쯤 뒤 다시 누르세요.
3. **저장하고 계속**을 누르고, 3단계의 아이디·비밀번호로 로그인합니다.
4. 시트 메뉴 **LabKeeper → 학교 정보 입력**에서 학교 이름과 관리 교사를 입력합니다. 웹 화면 왼쪽 메뉴 아래(메뉴를 접으면 위쪽 줄)와 로그인 화면의 "연결된 학교"에 보입니다. 바꿀 때마다 **환경설정 이력 탭**에 누가(구글 계정) 언제 무엇을 바꿨는지 남습니다.
5. 웹의 **설정**에서 학교급, 장부 양식 지역(기본 충북), 서명자 이름을 입력합니다.

연결 정보는 그 브라우저에만 저장됩니다. 다른 PC에서는 아래 접속 링크로 엽니다.

## 5. 다른 선생님 초대하기

1. **계정 관리**에서 선생님 계정을 만듭니다. 화면에 한 번만 보이는 **임시 비밀번호**가 나옵니다.
2. 같은 화면의 **우리 학교 접속 링크**에서 **복사**를 누릅니다.
3. 선생님께 **접속 링크와 임시 비밀번호**를 함께 전합니다. 선생님은 링크를 열고 로그인한 뒤 본인 비밀번호로 바꿉니다.

- 접속 링크는 운영 교사에게 직접 받은 것만 쓰세요. 링크가 지금 연결된 학교와 다른 곳을 가리키면 화면이 "연결을 바꿀까요?"라고 먼저 묻습니다.
- **스프레드시트 열기** 버튼으로 학교 시트를 바로 열 수 있습니다(운영 교사만).

## 6. 시트 탭 구성

시트를 직접 열어 봐도 읽기 쉽게, 탭은 한국어 이름으로 나뉩니다. 탭은 그 기능을 처음 쓸 때 자동으로 생깁니다.

- **기록 탭 (파란색)**: 환경설정, 계정, 교실, 보관장, 보관장 구역 (앞으로 시약, 시약 수불, 폐수·폐시약, 안전점검, 폐수점검, MSDS 참고자료, 교구, 교구 기준이 더해집니다)
  - 각 줄에 작성자·작성일시·수정자·수정일시·삭제자가 이름과 한국 시간으로 적힙니다. 앱이 쓰는 ID 칸은 오른쪽 끝에 있습니다.
- **이력 탭 (회색)**: 환경설정 이력, 계정 이력, 접속 기록, 교실 이력 (앞으로 시약 이력, 폐수·점검 이력, 교구 이력)
  - 왼쪽부터 일시 · 사람 · 표 · 대상 · 동작 · 바뀐 내용(예: "이름: 과학실 → 제1과학실")을 읽으면 됩니다. 회색 머리글의 오른쪽 칸은 앱이 쓰는 원자료입니다.
- 예전 영어 탭(Users, Rooms, AuditLog …)이 있던 시트는 새 코드가 처음 실행될 때 자동으로 새 탭 이름과 머리글로 바뀌고, AuditLog의 기록은 분야별 이력 탭으로 옮겨집니다.

## 6-1. 시트 메뉴 (LabKeeper)

| 메뉴 | 하는 일 |
|---|---|
| 학교 정보 입력 | 학교 이름과 관리 교사를 입력합니다(웹은 읽기만 함). 변경 기록은 환경설정 이력 탭에 남습니다 |
| 운영 교사 계정 만들기 | 계정이 하나도 없을 때 첫 운영 교사를 만듭니다 |
| 운영 교사 비밀번호 초기화 | 운영 교사가 비밀번호를 잊었을 때 임시 비밀번호를 만듭니다(그 계정의 기존 로그인은 모두 끊김) |
| 시트 구조 점검 | 표와 1행 머리글 이름이 맞는지 확인합니다(고치지는 않음) |
| 사본을 새 학교 시트로 시작 | **운영 중인 시트를 복사한 사본**의 계정·기록을 모두 지우고 새 학교 시트로 만듭니다. 되돌릴 수 없습니다. 원래 시트(사본이 아닌 시트)에서는 동작하지 않습니다 |
| 이 사본을 계속 쓰기 | 운영 중인 시트의 사본을 데이터 그대로 학교 시트로 삼습니다(아래 "시트 옮기기") |
| 운영 종료 (이 시트 잠그기) | 이 시트에 연결된 웹 화면을 잠그고 안내 문구만 보여 줍니다. 기록은 지우지 않습니다 |
| 운영 종료 풀기 | 잠근 시트를 다시 씁니다 |
| 배포용 원본으로 초기화 | 배포 관리자용. 시트를 비워 다른 학교에 나눠 줄 원본으로 만듭니다([배포 관리자 안내](maintainer-guide.md)). 학교 시트에서는 쓰지 마세요 |
| 사용 가이드 | 이 안내를 짧게 보여 줍니다 |

> ⚠️ 각 시트 **1행의 머리글 이름은 바꾸지 마세요.** LabKeeper는 머리글 이름으로 열을 찾습니다. 열 순서를 바꾸거나 오른쪽에 내 열을 더하는 것은 괜찮습니다.

> **운영 교사가 바뀔 때(전근 등)는 "사본 만들기"가 아니라 시트의 소유권을 넘기세요.** 시트 **공유**에서 새 운영 교사를 편집자로 추가한 뒤 **소유권 이전**을 하면, 같은 파일을 그대로 쓰므로 기록과 웹 앱 주소가 모두 유지됩니다. 웹 앱 배포는 원래 배포한 사람의 권한으로 실행되므로, 소유권을 넘긴 뒤 새 운영 교사가 **배포 관리 → 수정 → 새 버전**으로 한 번 다시 배포해 두세요(주소는 바뀌지 않습니다).

### 시트 옮기기 (소유권을 넘길 수 없을 때)

교육청 학교 계정 → 개인 Gmail처럼 소유권을 넘길 수 없으면 사본으로 옮깁니다.

1. 새 운영 교사가 원래 시트를 **사본 만들기**로 자기 드라이브에 복사합니다.
2. 사본에서 **LabKeeper → 이 사본을 계속 쓰기**를 누릅니다. 학교 이름과 계정 수를 확인하고 계속합니다. 기록과 계정은 그대로 남습니다.
3. 사본에서 웹 앱을 **새 배포**하고(2단계와 같음), 새 접속 링크를 모든 선생님께 다시 보냅니다. 새 링크를 열면 "이름은 같지만 다른 스프레드시트" 확인이 뜨니 미리 알려 주세요. 선생님들은 다시 로그인합니다(아이디·비밀번호는 그대로).
4. **원래 시트에서 LabKeeper → 운영 종료**를 실행합니다. 안내 문구에 "새 접속 링크는 ○○○ 선생님께 받으세요"처럼 적어 두면, 옛 링크로 들어온 선생님이 그 문구를 봅니다. 이렇게 해야 기록이 두 시트로 갈라지지 않습니다.

> 운영 중인 시트를 "사본 만들기"로 복사하면 그 사본에는 원래 학교의 계정과 기록이 들어 있어서, 화면이 "운영 중인 시트의 사본입니다"라며 막습니다. 새 학교를 시작할 때는 항상 **1단계의 원본 링크**로 복사하세요. 시트를 옮기는 경우라면 위 "시트 옮기기"를 따르세요.

## 7. 코드 업데이트 (화면이 "옛 버전"이라고 할 때)

공용 화면이 새 기능을 쓰기 시작하면, 학교 시트의 코드도 새 버전이어야 합니다. 화면에 "학교 시트의 프로그램이 옛 버전입니다"가 나오면:

1. 저장소의 [`gas/dist/LabKeeper.gs`](https://github.com/mrdoolee/labkeeper_project/blob/main/gas/dist/LabKeeper.gs)를 열고 오른쪽 위 **복사** 버튼으로 전체를 복사합니다.
2. 시트의 **확장 프로그램 → Apps Script**에서
   - 파일이 `LabKeeper` 하나라면: 내용을 모두 지우고 붙여 넣습니다.
   - 예전 방식으로 여러 파일(`Auth`, `Code`, `Db` …)이 있다면: 모두 삭제하고(파일 옆 ⋮ → 삭제) **+ → 스크립트**로 `LabKeeper` 파일 하나를 만들어 붙여 넣습니다.
3. **저장** 후 **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**를 누릅니다.
   - "새 배포"를 누르면 URL이 바뀌어 모든 선생님이 다시 연결해야 하니, 꼭 **배포 관리 → 새 버전**으로 하세요.
4. 화면에서 **다시 확인**을 누릅니다.

데이터(시트 내용)는 코드 업데이트로 바뀌지 않습니다.
